Security check

Does Claude Account Manager send credentials or data anywhere?

An audit of every network call, spawned process and storage location in the account-manager-for-claude VS Code extension. It answers one question: do OAuth tokens, account details or usage data leave the computer, and if so, where do they go?

Claude Account Manager v1.0.8

Result: no data leak found

No credentials or user data go to any third party. OAuth tokens are sent only to Anthropic's own endpoints, which the extension needs in order to work.

  • All outbound requests go to hardcoded Anthropic hosts (platform.claude.com, api.anthropic.com). No setting can redirect them.
  • The extension has no telemetry, analytics, crash reporting or tracking.
  • The webview panels are blocked from making network requests by their Content Security Policy.
  • Tokens are kept in VS Code's encrypted SecretStorage and are never logged or copied to the clipboard.

How the check was done

  1. Searched all source code for network primitives: fetch, Node http/https/net, XMLHttpRequest, WebSocket, sendBeacon, axios/undici, and vscode.env.openExternal.
  2. Searched for process execution (child_process, spawn, exec) and for the VS Code telemetry API.
  3. Read every match in full to see exactly which data each request or process receives.
  4. Checked the Content Security Policy of each webview, along with every image, script and stylesheet source.
  5. Traced where tokens are stored, and checked logging, clipboard use and backup export.
  6. Listed runtime dependencies and install scripts from package-lock.json, and checked what .vscodeignore ships.

Things worth knowing

None of these is a data leak. They are behaviours a careful user may want to know about.

Info The extension identifies itself as Claude Code

Usage requests send User-Agent: claude-code/2.0.14, and every OAuth call uses Claude Code's public client ID. The endpoints are not officially documented, so Anthropic could change or restrict them, which would stop usage tracking or token refresh from working. (usage.ts:7, oauth.ts:13)

Info Usage polling runs in the background

With the default settings, the extension checks every saved account's usage with Anthropic every 240 seconds, using that account's token. If usage history is turned on, it checks every 60 seconds. You can turn this off with accountManagerForClaude.autoRefresh, after which it checks only at startup, on manual refresh, and when a used-up limit is due to reset.

Info Say Hi sends a real prompt

“Say Hi” sends a short prompt (Hi by default, haiku model) to Anthropic through the Claude CLI, on the selected account. This uses a small part of that account's usage. It only runs when you start it.

Limit This covers the source code, not the published package

This check covers the source code in the repository at commit 7b4c361. It does not compare that code against the VSIX published on the Visual Studio Marketplace. To be sure that package matches this code, build it yourself with npm run build:vsix, or unpack the published VSIX and search its dist/ files with the commands below.

Check it yourself

From the repository root, these commands list every network call and spawned process. The results should match the tables above.

# Every network call and external-link opener
grep -rnE "fetch\(|https?\.request|XMLHttpRequest|WebSocket|sendBeacon|openExternal" src webview

# Every hardcoded URL
grep -rnoE "https?://[^\"' )]+" src webview

# Every spawned process
grep -rnE "child_process|spawn\(|execFile|execSync" src

# Webview Content Security Policies
grep -rn -A6 "const csp" src/ui
